# Reproducible pinned-source evidence audit

Audit recorded 2026-11-04. Source inspection only; no Android image was built or
tested, no phone was accessed, and no proprietary Samsung binary was downloaded
or distributed.

The three research XML revisions resolve on the repositories' currently exposed
`lineage-18.1` branches. Their source differs materially from the separate
`old_device_*` historical trees cited in earlier notes. A branch name is evidence
of repository organization, not proof of a reproducible LineageOS build or an
Android version's compatibility.

Full source files, not copied snippets, are retained in
[`tests/fixtures/upstream`](../tests/fixtures/upstream/README.md). The inventory
binds the primary evidence to XML pins and records exact-byte SHA-256 plus the
upstream Git blob IDs. The kernel version is the **source** version; it does not
change the user-reported stock 4.4.177 kernel. No partition values are verified
against SM-A750F hardware by these files.

Run `python3 tools/check_source_evidence.py` and
`python3 -m unittest discover -s tests -v`. Integrity tests reject modified bytes,
floating revisions, mismatched XML pins, traversal, external symlinks, missing
or unrecorded files, and duplicate inventory entries. Source-fact tests cover
Clang/API 28/kernel version, requested defconfig, super arithmetic and matching
kernel command line. They validate evidence handling, not bootability.

## Samsung tooling and SLSI

`exynos7885-dev/hardware_samsung` exposes `lineage-18.1` at
`082709ec235fd60f55bff0fb0deb8eae12bf0622`. Its complete Apache-licensed
`mkbootimg.mk` is now a fixture. It resolves `TARGET_CUSTOM_DTBTOOL` as a **host
executable name**, so `dtbhtoolExynos` must be checked as a module/tool dependency
instead of misreported as a missing file. That script also conditionally includes
`system/tools/dtbtool/Android.mk` and builds Samsung boot/recovery image targets;
its existence alone does not validate modern build variables or output images.

Matching historical `exynos7885-dev/hardware_samsung_slsi-linaro_config` sources
are now found at `c7a3ba8a1d8e9a467284f8e4e36672b33494e5f8` (`lineage-18.1`).
Three full Apache source fixtures declare Exynos 7885/Linux 4.4 and select
`libhwc2.1`. Their sibling directory and interface requirements still need a
complete pinned checkout. See the updated dependency-discovery notes for exact
sibling pins and unresolved paths.

The previously discovered `Exynos2100-common` config candidate is separately
recorded at `6314d277fcefafe23122117b219ca66d0ab3e05c` (`lineage-21`). It selects
`hwc3` and invokes Soong configuration APIs absent from the historical common
config. These observable differences are why filename/platform matches alone
cannot approve substituting that candidate. Both fixture groups remain
`candidate-only`, and neither was added to the research XML.

Both Makefiles identify themselves as generated by the corresponding device
`setup-makefiles.sh`. They enumerate proprietary copy sources and modules; the
device list includes NFC configuration and firmware paths, and the common list
includes Widevine and modem-related files. No vendor Makefiles or blobs were
copied into the fixtures. Their existence and branch names do not establish
SM-A750F/A750FXXU5CVG1 extraction provenance, redistribution rights, ELF symbol
compatibility, or runtime HAL functionality. Those remain build blockers.
